# 适用性规则

先识别页面能力，再选择探针。没有适用证据时跳过，不为覆盖目录制造动作。

## 页面匹配

| 页面特征 | 优先探针 | 不自动执行 |
| --- | --- | --- |
| 菜单、链接、页签、面包屑 | 目标上下文、返回保留、入口可达性 | 猜测隐藏路由 |
| 列表、表格、卡片集合 | 筛选无结果、行级对象绑定、列表详情、明细汇总 | 未授权批量动作 |
| 新增、编辑、弹窗表单 | 必填恢复、格式错误、长文本、取消关闭 | 保存或提交 |
| 详情、摘要、只读面板 | 列表详情、字段层级、长内容布局 | 修改真实数据 |
| 状态标签、流程按钮、操作日志 | 状态动作矩阵、操作前后、刷新回显 | 提交、审批、驳回、撤回 |
| 异步加载、处理中、失败提示 | 等待、刷新、重试和恢复观察 | 制造大批量或外部故障 |

## 799 字符字段判定

适用：

- 多行文本、备注、说明、描述、意见、原因、标题或名称。
- 单行自由文本且从标签、帮助文本、已有数据或交接信息判断可能承载自然语言。
- 可安全清空、取消或恢复的 AI 自建数据表单。

排除：

- 密码、验证码、密钥、token 或任何敏感输入。
- 手机号、邮箱、URL、日期、时间、数字、金额、数量、证件号、编码和纯格式化字段。
- 搜索框、筛选关键字、富文本源码、文件路径和命令输入。
- 自动完成、标签选择器、枚举选择器或不可确认自由输入语义的控件。
- 正在编辑真实业务数据，或取消后是否恢复不明确的表单。

边界选择：

1. 需求交接、控件属性、计数提示或可靠页面文案给出最大长度时，以该长度为准。
2. 最大长度小于 799 时使用 `max-1`、`max`、`max+1`；若 `max+1` 可能触发持久化或不可恢复副作用，只做客户端安全范围。
3. 最大长度等于或大于 799，或完全未知时，才使用 799 字符。
4. 控件在 799 之前主动截断时，记录输入长度、实际值长度和提示；不要绕过控件限制注入更长值，除非用户明确要求安全专项。

## 799 字符确定性生成

在浏览器上下文中按以下等价逻辑生成 ASCII 值：

```javascript
const prefix = `HF799-${runId}-${fieldId}-`.replace(/[^A-Za-z0-9-]/g, "-");
const filler = "0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZ";
const value = (prefix + filler.repeat(30)).slice(0, 799);
if (value.length !== 799) throw new Error("HF799 payload length mismatch");
```

若前缀异常长导致补齐不足，先将 `runId` 和 `fieldId` 分别截为 40 个字符，再生成。输入后再次读取控件值长度，区分“生成值为 799”与“控件实际接收 799”。

## 写入适用性

满足以下全部条件才能使用已授权的 L1 写入：

- 用户选择允许创建并保存 AI 自建数据。
- 对象明确为本轮 AI 新建或用户明确指定可操作。
- 影响范围可见，不会触发外部通知、真实业务处理或权限配置。
- 保存失败或成功后的状态都能记录，且不要求未经授权的删除来恢复。

缺一项则降级为只填不存或只读观察。

## 单角色边界

- 当前角色能看到按钮，不证明其他角色看不到。
- 当前角色不能操作，不证明系统整体禁止该操作。
- 跨角色审批、数据隔离、字段权限和消息接收必须有第二角色证据；只有一个账号时保留为未覆盖。
- 可以验证当前角色内部的菜单、操作、字段和数据范围自洽性，但结论必须限定到该账号上下文。
