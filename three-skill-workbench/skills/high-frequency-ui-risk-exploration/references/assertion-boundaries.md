# 断言与定性边界

高频经验只决定“值得看什么”，不能直接证明“系统应该怎样”。结论必须绑定证据来源。

## 定性层级

| 分类 | 最低证据 |
| --- | --- |
| 确认缺陷 | 有可靠确认规则，且页面行为可复现地违反该规则 |
| 疑似缺陷 | 页面内部明显矛盾，或同一对象跨页面、操作前后结果不一致，但缺少完整业务口径 |
| 风险 | 高频模式命中且可能影响用户或数据，当前证据不足以判定缺陷 |
| 当前行为基线 | 实际观察到稳定行为，但不声明其业务正确 |
| 待确认 | 预期依赖需求、角色、配置、后端规则或未授权动作 |
| 工具阻塞 | 执行器、页面可控性或证据能力不足，不能归因于系统 |

## 断言来源强度

从强到弱：

1. 用户确认、可靠 PRD 规则或明确验收标准。
2. 同一系统内可验证的输入与回显、列表与详情、状态与日志、明细与汇总关系。
3. 可重复观察到的当前行为基线。
4. 高频风险经验和常见产品习惯。

第 4 类只能形成探索假设或风险，不能单独形成缺陷。

## 长文本结论

- 控件实际接收 799 字符，只能证明客户端接受该长度。
- 保存成功并刷新后完整回显，才支持当前字段在该路径下可持久化 799 字符。
- 被客户端截断且无明确规则来源时，记录行为和可用性风险，不直接判定长度错误。
- 保存失败时必须区分字段校验、服务端业务错误、权限、网络和执行器异常。
- 页面布局异常需要截图或等价视觉证据；仅有 DOM 值不能证明遮挡、重叠或溢出。

## 流程和角色结论

- 单角色只能得出当前角色结论，不能推断跨角色权限矩阵。
- 未执行提交、审批、驳回、撤回等动作时，只能记录按钮与当前状态关系，不能宣称流程闭环通过。
- 工具超时后先读取页面实际状态；页面已成功变化时不得记为系统失败。
- 未授权写入导致的未覆盖必须进入风险或覆盖边界，不得写成通过。

## 冲突处理

当需求交接与页面行为冲突：

1. 保留交接字段、证据等级和来源引用。
2. 记录页面当前行为、账号、对象、时间和证据。
3. 标记冲突影响的路径、测试资产和结论。
4. 有确认规则时按缺陷候选处理；只有推导或未知时按风险/待确认处理。

## 报告措辞

使用：

- “在当前账号、当前对象和当前页面路径下观察到……”
- “该结果与已确认规则……不一致，已形成可复现证据。”
- “由于未获保存/流程动作授权，服务端校验与状态闭环未覆盖。”
- “单角色条件下无法验证跨角色可见性和后续处理。”

避免：

- “系统支持 799 字符”，但只做了输入。
- “权限正常”，但只有一个角色。
- “流程通过”，但只看见按钮或状态标签。
- “没有问题”，但相关探针未执行或不适用。
